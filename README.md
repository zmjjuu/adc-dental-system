# 🦷 安德鲁牙科连锁管理系统 ADC

依据《ADC 拟开发项目与业务需求说明》（`adc_new_hw` 目录）实现的可运行系统，包含：

| 部分 | 位置 | 说明 |
| --- | --- | --- |
| **后端** | `backend/` | Python Flask + SQLite，实现设计文档 25 张逻辑表与 UC01—UC12 全部业务规则 |
| **网站** | `website/` | 由后端直接提供，按岗位（前台/牙医/财务/运营经理/总部经理）分权限操作 |
| **微信小程序** | `miniprogram/` | 原生小程序，在微信开发者工具中运行，功能与网站一致 |

> **注意**：GitHub 仓库是**源代码**，浏览器打开仓库地址只能看代码和文档，不能直接运行系统。老师查看本系统的三种方式见下文「给老师看的方式」。

## 一、给老师看的方式

### 方式 1：老师在自己电脑上运行（约 2 分钟，推荐写进作业说明）

老师需要：① 安装 Python 3.11+；② 下载本仓库（或让老师 git clone）；③ 运行：

```bash
pip install -r backend/requirements.txt
cd backend
python app.py
```

然后浏览器打开 **http://127.0.0.1:8000**，用下面的演示账号登录。首次启动自动生成演示数据。

### 方式 2：部署到免费云平台，给老师一个网址（体验最好）

代码已做好部署适配（`requirements.txt`、端口自动读取环境变量 `PORT`），任选其一：

- **Render（免费，推荐）**：仓库上传 GitHub 后，在 render.com 用 GitHub 账号登录 → New Web Service → 选择本仓库 → Root Directory 填 `backend` → Build Command 填 `pip install -r requirements.txt` → Start Command 填 `python app.py` → 部署完成后得到 `https://xxx.onrender.com` 网址发给老师。免费实例闲置后会休眠，首次打开约等 1 分钟；每次重新部署演示数据会重置为初始状态。
- **PythonAnywhere（免费）**：上传 `backend` 目录三个 py 文件 → Web 页签添加 Flask 应用 → 得到 `https://用户名.pythonanywhere.com`。

### 方式 3：微信小程序"体验版"给老师扫码（老师手机直接打开）

**测试号（touristappid）不能分享给他人体验**——它只在开发者本人的开发者工具里运行。要让老师在手机上用小程序，需要：正式 AppID + 后端部署到**小程序白名单内的 HTTPS 域名**。

> ⚠️ 注意：小程序体验版的 request 合法域名必须 **ICP 备案**，所以 Render/Vercel 等海外免费服务器**不能**用于体验版。推荐使用**微信官方云托管**（域名免备案自动接入、按量计费、可随时停服），完整逐步教程见 **[docs/体验版部署指南.md](docs/体验版部署指南.md)**，流程概览：
>
> 1. 确认 AppID 是你本人注册的（mp.weixin.qq.com）
> 2. 完善小程序信息（名称如含"牙科"审核不过可改中性名）
> 3. 开通微信云托管 → 连接本 GitHub 仓库自动构建（仓库根目录已备好 Dockerfile，监听端口 80）
> 4. 云托管域名加入「request 合法域名」→ 改 `miniprogram/utils/api.js` 的 BASE → 开发者工具「上传」
> 5. 后台「版本管理」选为体验版 → 「成员管理」把老师的微信号加为**体验成员** → 老师扫码即用

> 课程演示最省事的组合：**方式 1 + 方式 2** 给老师（网站直接点开用），小程序部分在 README 放**运行截图/录屏**（见「运行截图」一节），有条件的再走方式 3。

## 二、启动后端（自己开发时）

```bash
cd backend

```

- 网站地址：**http://127.0.0.1:8000**（手机和电脑同一 WiFi 时，用局域网 IP 也能打开网站）

## 三、网站使用

浏览器打开 http://127.0.0.1:8000 ，选择演示账号登录：

- **前台**：预约工作台（患者核对→可约时段→防冲突预约）、就诊管理（到诊登记/取消/改约/未到诊分类）、患者管理（逐项过敏）、开结算单
- **牙医**：我的接诊（过敏逐项复核确认→记录实际治疗→签署→更正版本链）
- **财务**：费用登记与分摊（无规则先挂待分摊）、季度核算（提交审批）、结算单核对
- **运营经理**：牙医与资质、诊所、跨店出诊（重叠拒绝）、治疗项目目录
- **总部经理**：取消率报表、标准化检查、季度审批、审计日志

## 四、微信小程序使用（开发者工具）

1. 安装 **微信开发者工具**（https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html）
2. 启动后端（见上）
3. 开发者工具 → 导入项目 → 目录选择本项目的 **`miniprogram`** 文件夹
4. AppID 填**测试号**（无需注册）或你自己的 AppID
5. 右上角 **详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**（project.config.json 已默认关闭 urlCheck，一般会自动生效）
6. 编译运行，登录任意演示账号

后端地址在 `miniprogram/utils/api.js` 的 `BASE` 中修改（真机体验版改为公网 HTTPS 地址，见方式 3）。

## 五、演示流程（对应设计文档场景）

1. **前台登录** → 预约工作台检索 `P-1001`（老患者陈雨桐，乳胶+树脂过敏、无邮箱）→ 选滨江门诊 C-B02、治疗"洗牙"（按资质筛选出李铭）→ 选时段 → 预约成功
2. **牙医李铭登录** → 我的接诊 → 对 P-1001 登记到诊（前台操作）→ 复核过敏 → 记录"洗牙 1×180 + 全景影像 1×150"→ 逐行签署
3. **前台** → 就诊管理 → 开结算单：**合计 330 元、两行明细、单号 INV-202611-xxxx**；重复开单返回原单号
4. 牙医对已确认治疗点"更正"→ 同单生成**版本 2**（原版本保留）
5. **财务登录** → 登记费用（分摊合计必须等于来源金额）→ 季度核算生成 Q4 草稿：有未确认费用时**不能提交审批**
6. **总部经理登录** → 运营报表：取消率分母只算已到期预约（未来预约单列）；季度审批批准 Q3 已生成版本（净利润 122000 元、基金 12200 元）
7. **运营经理登录** → 给牙医加跨店出诊：重叠时段会被拒绝

## 六、与设计文档的对应关系

- 数据库：25 张逻辑表与字段名完全沿用设计文档第 11 章（`backend/db.py`）
- 业务规则：预约冲突原子检查、状态流转（待到诊/已到诊/患者取消/诊所撤销/已改约/待核实/未到诊/治疗完成）、治疗版本与更正、一就诊一有效结算单（更正同单新版本）、费用分摊校验、季度核算（收入−耗材−运营费=净利润，基金=10%，个人奖金不自动计算）、取消率统计口径、审计留痕
- 界面原型：预约工作台/到诊登记/治疗记录/结算单/季度核算/运营报表，对应设计文档第 13 章图 14—16
- 验收：`backend/test_api.py` 覆盖 T01—T12

## 八、目录结构

```
adc_system/
├── backend/
│   ├── app.py            # Flask API + 网站托管（全部 REST 接口）
│   ├── db.py             # 建表 + 演示数据种子
│   ├── logic.py          # 业务规则（冲突检查/版本链/结算/季度核算/报表）

│   └── adc.db            # SQLite 数据库（自动生成，不入库）
├── website/              # 网站前端（原生 JS，无构建）
│   ├── index.html
│   ├── css/style.css
│   └── js/               # api / ui / app / 各岗位视图
├── miniprogram/          # 微信小程序（原生）
│   ├── app.js / app.json / app.wxss / project.config.json
│   ├── utils/            # api 客户端、格式化
│   └── pages/            # login/index/visits/visit/book/patients/patient/treat/invoice/costs/quarter/report/manage/me
├── docs/                 # 文档（截图清单、截图目录）
└── README.md
```
