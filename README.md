## 一、部署与访问

### 1.1 在线访问（当前部署）

- **网站**：https://adc-353510-13-1540267336.sh.run.tcloudbase.com
- **小程序**：体验版（ADC 日常记录），正式版待审核发布
- 部署环境：微信云托管（服务 `adc`，环境 `prod-d3gyx49ypd96d0cf0`）

### 1.2 本地运行（约 2 分钟）

环境要求：Python 3.11+。

```bash
pip install -r backend/requirements.txt
cd backend
python app.py
```

浏览器打开 **http://127.0.0.1:8000**。首次启动自动建库并写入演示数据（`backend/adc.db` 不入库，可随时删除重建）。

### 1.3 网站部署到其他平台（可选）

代码已做好部署适配（`requirements.txt`、端口自动读取环境变量 `PORT`），除微信云托管外也可部署到：

- **Render（免费）**：New Web Service → 选择本仓库 → Root Directory 填 `backend` → Build Command 填 `pip install -r requirements.txt` → Start Command 填 `python app.py`。免费实例闲置后休眠，首次访问约等 1 分钟。
- **PythonAnywhere（免费）**：上传 `backend` 目录 → Web 页签添加 Flask 应用。

> 注意：小程序体验版/正式版的 request 合法域名必须 ICP 备案，海外免费平台域名不可用；本项目的解决方案是微信云托管私有协议云调用（见 1.4），无需配置域名。

### 1.4 微信小程序部署

小程序通过 **微信云托管私有协议 `wx.cloud.callContainer`**（`miniprogram/utils/api.js`）访问后端，**无需配置 request 合法域名**，测试号仅限开发者工具调试，发布需正式 AppID。部署步骤：

1. 微信云托管创建服务，上传 `deploy/cloud-deploy.zip`（含 Dockerfile，监听端口 80）
2. 修改 `miniprogram/utils/api.js` 中的 `CLOUD.env` 与服务名
3. 微信开发者工具「上传」→ 公众平台后台「版本管理」设为体验版 / 提交审核

小程序还内置了**离线演示引擎**（`miniprogram/utils/mock.js`）：与后端同一套业务规则与演示数据，后端不可达时自动切换，保证断网时仍可完整演示全部流程。

完整的逐步部署教程见 **[docs/体验版部署指南.md](docs/体验版部署指南.md)**。

## 四、微信小程序使用（开发者工具）

1. 安装 **微信开发者工具**（https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html）
2. 启动后端（见上）
3. 开发者工具 → 导入项目 → 目录选择本项目的 **`miniprogram`** 文件夹
4. AppID 填**测试号**（无需注册）或你自己的 AppID
5. 右上角 **详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**（project.config.json 已默认关闭 urlCheck，一般会自动生效）
6. 编译运行，登录任意演示账号

后端地址在 `miniprogram/utils/api.js` 的 `BASE` 中修改（真机体验版改为公网 HTTPS 地址，见方式 3）。

## 五、演示流程（对应设计文档场景）

1. **前台登录** → 预约工作台检索 `P-1001`（老患者陈雨桐，乳胶+树脂过敏、无邮箱）→ 选滨江门诊 C-B02、治疗"洗牙"（按资质筛选出李铭）→ 选时段 → 预约成功
2. **牙医李铭登录** → 我的接诊 → 对 P-1001 登记到诊（前台操作）→ 复核过敏 → 记录"洗牙 1×180 + 全景影像 1×150"→ 逐行签署
3. **前台** → 就诊管理 → 开结算单：**合计 330 元、两行明细、单号 INV-202611-xxxx**；重复开单返回原单号
4. 牙医对已确认治疗点"更正"→ 同单生成**版本 2**（原版本保留）
5. **财务登录** → 登记费用（分摊合计必须等于来源金额）→ 季度核算生成 Q4 草稿：有未确认费用时**不能提交审批**
6. **总部经理登录** → 运营报表：取消率分母只算已到期预约（未来预约单列）；季度审批批准 Q3 已生成版本（净利润 122000 元、基金 12200 元）
7. **运营经理登录** → 给牙医加跨店出诊：重叠时段会被拒绝

## 六、与设计文档的对应关系

- 数据库：25 张逻辑表与字段名完全沿用设计文档第 11 章（`backend/db.py`）
- 业务规则：预约冲突原子检查、状态流转（待到诊/已到诊/患者取消/诊所撤销/已改约/待核实/未到诊/治疗完成）、治疗版本与更正、一就诊一有效结算单（更正同单新版本）、费用分摊校验、季度核算（收入−耗材−运营费=净利润，基金=10%，个人奖金不自动计算）、取消率统计口径、审计留痕
- 界面原型：预约工作台/到诊登记/治疗记录/结算单/季度核算/运营报表，对应设计文档第 13 章图 14—16
